# 周/月日历与课程改期

2026-11-11：训练页重新组织为日历与所选日期分区，资料核对入口整合进日历底部，补齐无课、历史空白、休息、加载和失败卡片；增加“回到今天”。事件标记同时使用形状、颜色与文字图例，详细交互及验证见 [训练页布局](training-home-layout.md)。

## 目的与流程

对应 PRD FR-202、FR-204。日历可切换周/月视图并选择日期；月视图按周一开始展示 42 个日期，支持跨年翻页和月末日期钳制。服务端返回账号时区和当地日期，客户端据此定位今天和判断历史课程。

休息/恢复事件有明确来源：

- 已保存的可训练时间规则中未选中的星期，且当天无正式课程，显示“固定休息日 · 可训练时间设置”。这是用户的固定时间安排，不是身体恢复评估。
- 实际课程含恢复动作且没有工作动作时，显示恢复课程事件。
- 接口继续只返回有来源的休息/恢复事件。2026-11-11 按用户新要求，训练页将已成功读取且没有课程或其他日程的日期统一展示为“休息日”，日历同步标记；这不向数据库新增休息事件，也不取消测试/赛事。

2026-11-11：按用户要求移除训练课程卡片上的改期入口，原改期独立页面与接口继续保留。原流程为：选择日期 → 服务端检查 → 显示冲突及替代日期 → 确认应用 → 新正式版本 → 查看日历。已记录和历史课程不开放改期。

## 服务与规则

`TrainingCalendarService` 负责日历读取，`WorkoutRescheduleService` 负责改期预览，`workout-schedule.ts` 负责领域约束，`TrainingApplicationService` 复用正式发布事务。

| 接口                                    | 输入与响应                                                                                           |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `GET /calendar?from&to`                 | 有效日期，含首尾最多 93 天；增加 `timezone/localDate/events`，课程 items 不变                        |
| `POST /workouts/:id/reschedule-preview` | `{scheduledDate,expectedPlanVersion}`；返回 `{workoutId,planVersion,from,to,conflicts,alternatives}` |
| `POST /workouts/:id/edit-proposal`      | 确认目标日期后复用人工编辑草稿；相同动作、名称、目的，改变日期                                       |
| `POST /proposals/:id/validate`、`apply` | 校验及确认；apply 带预览的 expectedProposalVersion、expectedBaseVersion 和幂等键                     |

改期检查比赛、已安排/已延期测试、固定不可训练日、单次时长上限、同日所有课程的总时长。**同一天允许多节课程**。距离目标无法可靠换算时长，暂时要求先改为时间目标再改期；不会给出虚假的可用时长结论。没有时间规则时引导补充。

替代方案在目标日期之后 14 天搜索，返回最多 3 个满足同一组约束的日期和剩余时间。没有结果时允许另选日期。预览为只读检查；正式日期变更在草稿创建、更新、校验和应用时均不可绕过约束，应用事务与既有写操作按用户锁串行化，并再次检查原课程记录和正式版本。

移至已有课程的日期时分配该日最大序号 + 1；原日期版本保留，不修改历史记录。请求不确定时客户端锁定本次选择，重试同一提案与幂等键；版本/日程冲突需返回日历刷新再操作。训练后的补给联动继续独立确认。

无数据库迁移。休息事件从时间设置派生，恢复事件从正式结构派生；不单独写入空课程。日历加载失败明确报错，不把失败当作空安排。
