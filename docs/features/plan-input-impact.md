# 资料变更后的未来计划处理

> 2026-11-11：影响检测新增个人身体资料快照。更新 FTP、身高、体重或训练经验后，用户可在影响页决定是否重新生成未来课程；测试建议不再要求单独复评。

## 目的与范围

对应 PRD FR-006、FR-104、AC-M02、§11。修改 FTP、目标或可训练时间后，保存事实与修改正式训练分开：查看影响 → 选择日期 → 保留、FTP 重算或重新规划 → 预览 → 确认 → 核对补给。

## 用户流程

- FTP 设置保存后停留在成功提示，选择“检查未来训练安排”或“完成并返回”。测试复评确认 FTP、目标管理保存后也提供检查入口。
- 已有计划的可训练时间保存后进入检查页；训练日历提供持久入口。
- “我的”页面不再展示“资料变更与未来训练”卡片；影响检查仍从训练日历或资料保存后的检查操作进入。
- `/plans/input-impact` 显示当前资料、未来未记录课程、旧 FTP 依据、功率换算、不可训练日及超时提示、阶段与测试核对提示。日期范围每次 1–84 天。
- “保留”需明确确认，记录决定而不发布训练版本。课程继续使用原 FTP 快照；今后规划使用最新资料。
- “仅重算 FTP”先保存可恢复草稿，再独立确认发布。百分比强度按新 FTP 换算；绝对瓦数、日期、时长、距离、重复结构、目的保持。
- “重新规划”复用范围生成任务；预览同时显示原课程完整区段与新课程。校验和确认应用沿用既有流程。
- 应用后到训练日历核对补给；训练变化通过已有日期签名将相关营养标为待核对，营养仍需独立生成、预览和确认。
- 已记录/历史课程不调整；范围外课程及尚未解决的其他资料影响继续提示。阶段与测试通过现有目标/复评入口单独确认。

## 实现与边界

阶段提示的目标名称优先使用去除首尾空白后的目标描述；描述为空时按目标类型显示中文名称，未知类型显示“训练目标”。提示同时列出发生变化的目标状态/版本、FTP、可训练时间或运动资料；依据一致时不显示变化提示。修复空描述被拼接为 `null` 的问题，不修改阶段或用户资料。

后端位于 `apps/api/src/modules/coach/plan-impact/`，按读取、策略、写入和 controller 拆分；契约为 `packages/contracts/src/plan-impact.ts`。移动端位于 `apps/mobile/src/features/plan-impact/`，路由位于受登录保护的 `app/plans/`。

正式发布的新课程在 `Workout.structure` 保存 `inputSnapshot`（FTP、可训练时间版本、目标版本/状态）与 `ftpSnapshotWatts`。未调整课程按原样复制；历史恢复保留原始依据。课程详情始终用课程快照换算执行瓦数，不使用当前 FTP 替换旧依据。手动编辑已有课程也保留旧功率依据，需要更新时通过显式重算或重排处理。

检查页直接比较当前事实与每节课程的依据，因此 FTP 设置、测试确认 FTP、旧版目标/建档接口等所有保存路径均可检测，无须给每个入口另外制造变更事件。对于没有旧快照的历史课程，显示“缺少依据/待核对”，不推测旧 FTP，也不回填当前值；可明确保留或重新规划。

保留决定按课程稳定身份及日期、目的、区段内容匹配，跨正式版本的未修改副本仍有效。匹配当前资料后不重复提示；后续新资料变化会重新提示。FTP 重算仅更新 FTP 部分，不能清除目标或可训练时间影响。

指纹包括账号当地日期、当前资料、正式版本、课程、实际反馈、阶段、赛事/测试及保留决定。生成前、模型结果落库前、AI 草稿校验/应用前与 FTP 重算应用前再次核对；任何依据变化返回冲突，禁止旧草稿发布。生成和决定本身不改变正式版本，也不清除待核对状态。

## API

均位于 `/api/v1`，需要本人 Access Token。写入需要 `Idempotency-Key`，范围请求含 `{fingerprint,startDate,endDate}`。

| 方法 | 路径                                      | 行为                                                                |
| ---- | ----------------------------------------- | ------------------------------------------------------------------- |
| GET  | `/plans/input-impact`                     | 只读影响、受保护数量、处理历史及可继续的生成任务                    |
| POST | `/plans/input-impact/decisions`           | 范围请求加 `action: KEEP或FTP_RECALCULATE`；记录保留或创建 FTP 草稿 |
| GET  | `/plans/input-impact/decisions/:id`       | 本人的不可变处理详情/草稿预览                                       |
| POST | `/plans/input-impact/decisions/:id/apply` | 重新核对依据后原子发布 FTP 重算版本                                 |
| POST | `/plans/input-impact/generate-proposal`   | 202 返回范围重排任务；使用当前活跃主目标，否则取一个活跃目标        |

AI 范围草稿响应新增可选 `planImpact`，包含范围指纹、原课程详情和生成时 FTP。共享 `weekGenerationInputSchema.planImpact` 只允许独立 RANGE_PLAN 日期范围，不可混入赛事、测试、阶段复评或周期复盘。缺少活跃目标时可以保留或重算 FTP，重新规划需先恢复/创建目标。

错误：401 未登录；404 不存在或非本人；400 无受影响课程/缺少重算依据；409 指纹、范围或幂等冲突。页面保留错误并可返回刷新影响；网络结果不确定时复用原请求键和决定 ID。任务记录由服务端保存，重新进入页面可继续查询。

## 数据、事务与迁移

新增 `PlanInputDecision`，保存用户、动作、状态、不可变范围/资料/原课程证据、结果及请求键，按用户/状态/时间索引；用户删除时级联清理。

迁移：`20261106160000_plan_input_decisions`，仅新增表和索引，不修改旧业务数据。Prisma generate 后通过 migrate deploy 应用。回退应用代码时可保留新增表和 JSON 快照；不删除决策记录或历史版本来回滚训练，训练回退使用已有版本恢复流程。

决定与正式应用均使用用户行锁事务；KEEP 同键重试返回相同决定；同一 FTP 草稿重复确认返回相同正式版本；跨决定复用确认键返回冲突。可训练时间保存也使用相同用户锁，避免与确认发布交错。

## 验证与手工路径

自动化：`apps/api/test/plan-input-impact.e2e-spec.ts`；App `features/plan-impact/__tests__/plan-impact.test.tsx`，以及更新的 FTP 设置测试。模型使用 stub，不调用付费真实模型。

1. 在 FTP 200 W 时发布一节 70% FTP 课程，然后保存 220 W。正式课程仍为 140 W；检查页显示重算后的 154 W。
2. 选择一天保留，确认不增加正式版本；其他日期仍待处理。再次改变 FTP 应重新提示。
3. 选择一天创建 FTP 重算草稿，未确认前正式计划不变；确认后仅该日快照更新，绝对瓦数保持，旧版本及范围外课程不变。
4. 缩短训练时间/取消一个训练日后，检查超时与不可训练日提示。生成重排，比较完整旧新课程；确认发布后核对补给。
5. 草稿生成后新增反馈、再次修改资料或执行保留决定，旧草稿应拒绝应用；刷新后重新选择范围。
6. 离开检查页后重新进入，继续已有任务或 FTP 草稿；暂时断网重试不重复发布。旧课程缺少 FTP 依据时只能保留或重规划。
