# 移动端首页 H01

## 目的与范围

首页回答“今天练什么、吃什么”，按 `RidePilot_UI/AGENTS.md` 和 H01 参考保持黑金暗色、训练照片 Hero、结构图、身体状态和饮食分组。仅展示正式计划真实数据；身体状态仍标为待评估，阶段、赛事和综合身体评估不在本次实现范围。

## 数据与操作

- 首页进入、下拉刷新、返回前台及跨日均只请求一次 `GET /home/today`。服务端按账号时区确定日期，聚合首页昵称、正式计划、当天课程、下一节课程和当天饮食。训练和饮食分别返回 READY / UNAVAILABLE，不把服务失败伪装成无计划。
- 训练概览由服务端领域服务在 Repeatable Read 事务内读取同一正式计划快照、课程和实际记录，避免正式版本切换时把状态、当天课程与下一节课程拼成不同版本。
- 今日多节课程分别显示标题、目的、目标、图表和完成状态。查看课程进入 `/workouts/[workoutId]`；单节 AI 调整直接进入 `/workouts/adjust?workoutId=...&source=home`，记录完成情况直接进入 `/workouts/feedback?workoutId=...&source=home`，不经过课程详情和抽屉。
- 反馈展示完成/部分完成/跳过、实际时长和 RPE；已记录课程不重复开放记录或调整。详情展示完整反馈。
- 没有正式计划时显示 AI 建计划和手动创建入口；已有正式计划但当天没有课程时显示“今天暂无训练安排”，提供日历、手动添加和下一节真实课程，不自动认定为休息日或补课。没有下一节时说明暂无后续安排。
- 饮食展示当天正式餐次、补给、时间、营养估算来源及成分警告，进入现有饮食页查看或替换。无训练日也独立显示饮食；无饮食计划引导生成草稿。
- 页面支持原生下拉刷新，首次加载与后续刷新统一使用一个刷新指示，不再展示多个区块 loading；顶部不显示正式版本及“刷新今日安排”操作栏。
- 页面重新聚焦、App 回前台和账号时区跨日时重新读取。过期异步响应不能覆盖较新读取。同日失败保留缓存并显示错误；有错误或正在刷新时暂停训练写入口。跨日不展示前一天的课程和餐次。
- AI 生成/应用失败保留备注与草稿；反馈失败保留所有表单输入。从首页进入的单节调整或反馈成功后直接回首页并刷新当天状态；详情进入的反馈回详情重新读取，调整发布后回训练日历读取新版本，避免停留在旧课程 ID。饮食页也按账号时区读取当天。

## 接口

所有调用均使用 Access Token，不在 App 直连数据库或模型。

| 接口              | 用途                                               |
| ----------------- | -------------------------------------------------- |
| `GET /home/today` | 首页唯一读取接口；服务端确定当地日期并聚合所有区块 |

共享契约为 `homeTodayResponseSchema`。只返回首页需要的用户 ID、昵称和时区，不附带手机号或身体档案。接口鉴权、部分失败和字段结构见 [首页 API](../api/home.md)。

## 验证范围

移动端测试覆盖真实课程/餐食入口、多节课程、无计划、无课日、无饮食计划、完成状态、独立失败、下拉刷新、缓存保留、前台刷新、账号时区跨日及旧请求竞争。课程路由测试覆盖反馈深链、失败保留输入、成功回显、单节调整及应用超时使用原幂等请求重试。

API 集成测试覆盖下一节课程鉴权/归属/排序/空结果，记录后跳过课程，发布新版本后保留实际记录，以及确认前新增反馈阻止覆盖。真机视觉和手势体验仍需设备验收。
