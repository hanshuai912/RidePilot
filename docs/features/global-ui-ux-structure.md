# 全局页面结构与信息层级优化

## 目的与范围

2026-11-13，依据 [全局 UI/UX 诊断](../reviews/global-ui-ux-diagnosis-2026-11-13.md) 实施移动端结构调整。优先解决数据口径、草稿判断、主要操作和失败恢复，再减少首页及列表中的重复展开内容。沿用黑金暗色主题、现有路由、接口和业务功能。

本轮没有新增训练能力、预测指标、短信服务、实时骑行页面或营养推荐算法。所有 AI 结果继续经过草稿、校验、预览和用户确认后应用；手动课程仍使用原有明确保存流程。没有 API、共享契约或数据库迁移，也没有增加依赖。

## 训练数据口径

- `training/model/segment-totals.ts` 统一计算每段目标乘重复次数，时间与距离分别汇总。原组件的导出继续兼容既有调用。
- `coach/model/proposal-summary.ts` 将课程数与去重后的日期数分开，草稿概览与预览复用同一结果。
- 回归样例：同一天两节课，每节为 5 分钟重复 3 次，结果为 **1 个训练日、2 节课程、30 分钟**。距离动作单独累计，绝不换算为时长。
- 结构图标题改为“计划区间中值”，避免被当成实测均值；补充时间轴起点、中点和终点。混合课程明确提示图中未包含的距离动作，纯距离课程显示文字目标。
- 比较图按每种强度单位取前后两份课程共同的刻度上限，W 与 %FTP 仍分轴。横轴分别显示各自课程时长，不能用相同图宽推断相同时长。
- 存在历史 FTP 快照时，动作行先显示可执行瓦数，再显示对应 FTP 百分比；不使用当前 FTP 改写历史目标。

## 实现边界与维护

新增 `components/ui/Disclosure.tsx` 供真实有次要详情的模块复用，折叠按钮提供 `expanded` 读屏状态。折叠只影响展示，不改变已有数据及可执行操作；需要编辑的输入由其原有父状态持有。

营养页异步编排从屏幕提取到 `nutrition/hooks/useNutritionPlan.ts`，生成入口提取为 `NutritionGenerationCard`。接口、版本校验、幂等请求和应用顺序保持原实现。`CoachScreen` 的既有流程状态机未重写，本轮只调整页面文案与组件装配。

保留历史及兼容路由，不恢复未注册的测试排期页，不引入新导航层级。训练日历、教练状态/聊天、参数表单、资料影响和赛事/目标预览继续复用原页面或本轮调整后的共享组件，并非把诊断中的 59 个路由全部重新绘制。

补给日期范围和赛事日期仍可按现有表单输入；本轮仅将“手动添加训练”接入已有的未来日期选择器，没有为其他业务擅自增加日期上下限。大列表的进一步虚拟化和少数历史兼容页面的专门布局仍需独立评估。

## 验证与验收

自动化覆盖重复次数与训练日统计、比较图刻度、混合/纯距离提示、草稿阻断信息顺序、折叠后的编辑路径、营养弹窗内错误与输入保留、创建按钮就绪条件，以及既有生成/校验/确认、返回、版本冲突和失败重试流程。

本轮先在独立临时目录运行原 HEAD 的三个失败用例，确认原先就存在的测试断言过时：目标浏览仍断言请求已不再使用的测试排期接口；教练测试仍断言已移除的版本标签。保留这些用例，分别改为验证目标浏览不引入测试排期依赖，以及旧课程摘要、版本不匹配提示和日历恢复入口。未删测试或跳过失败用例。

手动验收建议：

1. 在首页分别检查一节、多节、已记录课程，展开餐次与状态依据，验证原路由仍可达。
2. 打开含重复动作及距离目标的训练草稿，核对两处统计；在阻断状态下查看限制，编辑候选后回预览，确认正式计划没有提前改变。
3. 记录实际训练后查看详情，确认记录优先于完整计划结构，历史课程仍不可调整。
4. 切换查看主、次、暂停目标，检查说明中的综合规划范围，浏览其他阶段后验证生成条件未改变。
5. 在营养档案、替换、份量编辑中模拟保存失败，检查错误在弹窗内、输入不丢失，重试成功后再确认应用。
6. 查看赛事分组、加载失败重试、编辑字段错误和赛事管理/结果折叠入口。
