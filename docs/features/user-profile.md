# 用户信息与运动档案

## 1. 目的与范围

实现 PRD V1.4 的 `GET/POST /api/v1/me/profile`。返回当前账户的页面昵称、脱敏账号状态和基础运动档案；POST 局部更新只处理显式字段。FTP 历史、训练时段、饮食禁忌、正式目标和密码安全流程不在本功能内。

## 2. API 与业务规则

接口详情见 [用户信息 API](../api/profile.md)。所有请求需要 Access Token。`displayName` 允许重复且不参与登录；未设置显示“骑行者”。手机号、验证状态、密码和 `userId` 只读；POST 的未知字段拒绝。性别为空或“不愿透露”不阻断训练。未提交字段不变，支持空值的字段可用 `null` 清空。

## 3. 数据与并发

`users` 增加昵称、时区、地区和档案版本，`athlete_profiles` 保存一对一运动字段。POST 在事务内更新并 upsert 档案；可传 `expectedVersion` 进行乐观锁，过期版本返回 409，不静默覆盖其他请求。迁移及字段说明见 [用户档案数据](../data/user-profile.md)。

## 4. 测试与验证

`apps/api/test/profile.e2e-spec.ts` 在独立测试库覆盖默认空档案、手机号脱敏、昵称和档案字段局部更新、字段保留、未知/只读字段拒绝、版本冲突和未授权访问。已通过 `pnpm --filter @ridepilot/api test:integration`：5 个测试套件、26 个测试通过。用户档案迁移已应用到开发库和测试库；类型、构建、lint 和格式检查随本任务执行。

## 5. 未决与后续

手机号国家格式、特殊符号规则、年龄段最终选项和性别产品口径仍按 PRD 状态管理。训练时段、能力测量、饮食档案和正式目标应各自建立领域接口，不扩张本接口。
