# 首次建计划接入真实饮食档案

日期：2026-11-13

## 行为

首次建计划的“饮食与禁忌”使用饮食模块的同一份服务端档案，替代原先仅在引导中记录的字符串状态。

进入此步骤读取本人 `GET /nutrition/profile`。已有档案完整回显饮食方式、多项习惯、过敏原、限制、补充说明、常吃食物和用餐时间；仅在明确返回 404 时初始化新档案。网络或鉴权错误不会被当成未建档，不展示可覆盖原档案的默认表单。

右上角“生成”先校验和保存饮食档案，再发起训练草稿生成。更新携带读取时的 `expectedVersion`，首次创建不传版本。保存失败停留当前页并保留输入；保存期间禁用表单和返回，防止重复点击。档案未变化时跳过 PUT，避免无意义地增加版本、使既有营养草稿过期。保存超时后读取并比对内容，若服务端已经成功保存则继续；若不能确认成功，保留输入和错误，允许用户重试。

版本冲突保留本页修改并阻断继续生成，提供显式“重新读取饮食档案”。页面说明重新读取会替换未保存修改；重新读取成功后显示最新档案供用户核对。返回其他引导步骤再回来会保留本次编辑。

## 页面与复用

- 饮食方式单选，习惯、过敏原和禁忌分别多选；提供清空过敏原/限制的明确选项。
- 各组采用短标题、辅助说明、可换行选项和至少 48pt 的触控区域，统一黑金样式。
- 选择“其他限制”时说明必填；输入保留 200 字上限。
- 常吃食物和用餐时间放入可展开区域，支持修改并保留已有餐型、时间和食物，不用默认三餐覆盖已有档案。
- `NutritionProfileForm` 同时用于引导页和饮食页的档案弹层；`NutritionChoiceGroup` 统一单选/多选语义和反馈，兼顾原生与 Web 的 checked 状态。
- 引导页显示首次建立、已同步、待保存和保存状态，移除“仅本次引导/暂不提交”文案。预览与确认页同步使用真实档案摘要。

## 生成边界

饮食档案通过既有独立接口保存；不会将本地中文标签硬塞进训练生成请求。营养生成服务从数据库读取该档案，将真实偏好纳入餐食与训练补给上下文，并执行既有营养规则校验。

本次“生成”继续创建训练草稿。正式训练应用后，可通过既有训练补给联动入口生成餐食与补给；训练、营养保持独立的草稿、预览与确认流程。保存档案本身不会创建餐次或替换正式饮食计划。

无 API 契约、数据库、依赖或迁移变更。沿用当前账号鉴权、服务端归属查询与饮食档案乐观版本检查。本次用户要求替代早期产品文档中“引导饮食字段仅本地暂存”的限制。

## 验证

回归测试覆盖：已有档案回显与隐藏字段保留、首次建档、读取失败重试、服务端版本、未修改时跳过写入、保存失败保留输入、冲突恢复、超时成功核对、多选语义、其他限制与时间/食物校验，以及先保存后生成、重复点击防护、首页不额外加载饮食档案。

服务端集成测试使用本机隔离的 `*_test` PostgreSQL 和 Redis DB 1，覆盖档案保存后重新读取、营养生成上下文使用保存的偏好、过期版本拒绝、OTHER 说明校验、鉴权和账号隔离，并回归训练补给联动。模型使用测试替身。
