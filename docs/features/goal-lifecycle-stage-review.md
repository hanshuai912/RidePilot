# 目标生命周期与阶段复评

## 范围与入口

对应 PRD M02 FR-101～106、M05 FR-405～406、M11 与 §3.5.7。目标列表可建立独立目标；目标详情进入目标管理；阶段时间线和测试详情进入阶段复评；周期复盘提供目标延期、完成及结束入口。首次训练建档向导保留。

目标支持 FTP、耐力、爬坡、赛事和自定义类型，可填写可观察的达成条件、期望日期及主次。FTP 目标可填写目标 W 或 W/kg；同时填写时规划优先使用 W，功体比差距按当前体重单独核对。评价呈现当前 FTP、实际差距、剩余天数、每周可用分钟数和缺失资料，说明不确定性；不设未经确认的增长速度、运动学达成阈值或保证。

## 用户闭环

1. 新建目标先查看事实评价，再确认保存。已有目标的调整、延期、暂停、恢复、完成、结束及下一目标，必须先查看变更预览并确认。
2. 预览列出原值与新值、未来正式课程、关联测试、阶段及其他活跃主目标的影响。目标写入与决策记录同一事务保存；不会自动修改课程、测试或营养。
3. 同时只通过本功能建立一个活跃主目标。已有主目标时，新目标可先设次目标，再通过变更预览切换；其他活跃主目标在确认事务内降为次目标并递增版本。
4. 暂停目标可恢复，期限已过时必须先填写新的有效期限。完成须先填写达成条件，用户在理由中确认实际证据。`CLOSED` 的 `COMPLETED` 与 `STOPPED` 分别表示用户确认完成和主动结束。
5. 已关闭目标保留历史，可单独建立下一目标。新目标使用新 ID，旧目标及其计划历史保留。
6. 阶段复评先保存可观察的达成条件，再核对阶段日期内截至今天的执行统计、测试记录与来源。尚未开始的阶段显示空统计，不能确认达成。
7. 用户选择达到预期 / 尚未达到 / 证据不足，以及保持 / 延长 / 调整 / 进入下一阶段，填写理由、预览并确认。每次保存保留不可变的事实快照和决定。
8. 保持或进入下一阶段生成对应阶段的课程草稿；调整可按日期生成课程或重新规划阶段；延长必须先生成并确认新阶段安排，再从目标详情规划课程。所有生成都需主动点击，正式应用继续使用已有预览、校验和确认流程。

日期结束不等于达成；训练完成率不等于能力进度；复评不自动推进阶段或更新 FTP。无达成条件只能记录证据不足；无测试允许用户记录其他可观察证据，不冒充已有实测。进入下一阶段要求用户确认达成、存在尚未过期的有效下一阶段且目标活跃。保持日程已结束的阶段只能保留复评，继续训练须延长或调整。

## 实现边界

- 共享契约：`packages/contracts/src/goal-lifecycle.ts`、`stage-review.ts`。
- 后端：`apps/api/src/modules/coach/goals/` 的 controller、service、repository、policy 与 scope；现有阶段生成、范围生成、草稿校验及建议中心复用同一证据校验。
- 移动端：`features/goals` 的目标表单、评价、管理与复评页面；hook 分离持久化和生成状态；`StageReviewEvidenceCard` 在阶段、课程预览展示保存时依据。
- 后续生成绑定 `stageReviewId`。新复评替代旧决定；达成条件、训练反馈、测试、目标版本、FTP、资料、可用时间、正式计划版本或当地日期变化会使旧依据失效。提交、模型完成、阶段确认、课程校验和应用均重新检查。
- 待处理建议只读投影失效状态，读取页面不生成或应用。已确认阶段的来源复评作为历史保存，不因旧阶段被归档而把新正式阶段标成失效。
- 复评历史与目标决策接口最近各返回 30 条。阶段复评返回最近 30 个关联生成任务，可重新打开已有草稿或继续查询原任务；重进页面不会重新调用模型。通用指标体系、自动能力判定、自动调整营养及真机/真实模型验收不在本次交付范围。

## API

所有接口使用 Bearer 鉴权及用户归属校验。UUID、日期、长度及枚举由共享 Zod schema 校验；新增接口的 Swagger 请求和响应引用同一契约。

| 方法 | 路径（`/api/v1`）           | 用途                                                        |
| ---- | --------------------------- | ----------------------------------------------------------- |
| POST | `/goals/evaluate`           | 新目标事实评价，不调用模型                                  |
| GET  | `/goals/:id/overview`       | 目标事实、评价及最近决策                                    |
| POST | `/goals/:id/change-preview` | 目标变更、影响列表和 fingerprint                            |
| POST | `/goals/:id/changes`        | 提交 change + fingerprint，必填 Idempotency-Key             |
| GET  | `/stages/:id/review`        | 当前证据 snapshot 和复评历史                                |
| PUT  | `/stages/:id/criteria`      | criteria + expectedVersion                                  |
| POST | `/stages/:id/reviews`       | fingerprint、expectedReviewId、结论、决定、理由，必填幂等键 |

`POST /goals` 兼容既有调用，新增可选 Idempotency-Key；移动端新建目标会提供。原 PATCH 仍受状态与版本保护，混合状态/字段修改拒绝，建议客户端改走变更预览。阶段和范围生成请求新增可选 `stageReviewId`，响应携带保存时复评依据。

## 数据、安全与错误

迁移 `20261106090000_goal_lifecycle_stage_reviews` 增加目标条件/目标 W/关闭原因、阶段条件版本、复评记录、目标幂等决策记录与阶段草稿复评来源 JSON。均为新增 nullable 字段或有默认值字段，无已有数据回填及删除。

旧目标、旧阶段可继续读取，条件为空时提示补充；不能凭旧日期自动确认达成。迁移已在本机 `ridepilot_test` 验证，并按用户授权应用到本机开发库 `ridepilot`；正式环境尚未部署，须按既有部署流程执行 migrate deploy。回退应用时保留新增表列，避免丢失用户决策；不提供删除历史的逆向 SQL。

写操作在用户行锁下运行，版本和指纹防止跨端覆盖，用户幂等键唯一且校验请求哈希。不同用户访问返回 404，未登录返回 401；版本、指纹或幂等冲突返回 409；非法状态与无效决定返回 400。

移动端保存/生成失败保留输入，响应不确定时沿用同一幂等键和生成任务；409 刷新证据并要求重新预览。提交中禁重复操作与离开，未保存变更离开需确认。
