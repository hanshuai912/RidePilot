# AI 教练移动端训练计划

本功能将 O01 高保真原型的首次建计划路径接到当前骑行训练 API。AI 教练 Tab 通过正式计划状态接口区分首次引导与已有计划；首页也按同一状态区分无计划和当日无训练安排。实现位于 `apps/mobile/src/features/coach/`，资料页的 FTP 组件位于 `apps/mobile/src/features/profile/components/FtpMeasurementCard.tsx`。

已有正式计划时，AI 教练现在进入持续协作的状态中心，而不是再次打开首次建计划表单。状态中心提供重新规划、赛后恢复、训练反馈和准备比赛四个入口；每个入口先让用户选择影响范围，再填写近期变化，之后复用训练草稿的“生成、预览、校验、确认、应用”生命周期。这样可以把“上周刚完成半马，本周恢复、下周开始正式训练”表达为一份可检查的恢复草稿。

AI 教练步骤使用 Expo Router 嵌套路由承载：`/(tabs)/coach` 是状态中心，`/planning`、`/basics`、`/goal`、`/schedule`、`/nutrition`、`/loading`、`/proposals`、`/diff` 和 `/success` 分别对应规划、资料、生成和确认页面。`CoachFlowProvider` 只负责跨路由保存当前草稿状态，页面前进、返回和重试均通过路由操作完成，不依赖同一页面内的组件切换。

首次建计划各步骤的表单和页面壳分开放置；`useInitialPlan` 统一协调服务端资料版本、生成任务、草稿校验和应用状态。已有计划的本周与下周快捷入口当前复用同一草稿生命周期；接入单课、赛事、复评等更多场景时应另建场景 Hook。

## 与原型的差异

- 原型允许无 FTP，当前用户确认的 AI 骑行训练规则要求有效 FTP；手动课程保留原有绝对功率路径。
- 原型是两套四周候选。当前 API 一次返回一份一周草稿；当前交互展示一份真实推荐草稿，并保留后续扩展多候选的位置，不在一次响应中伪造第二套方案。`stageSummary` 和 `assessmentSuggestion` 是说明文字，尚未自动创建阶段或测试事件。
- 训练周期只作为生成上下文，正式日历仍按近期一周滚动发布。饮食与禁忌当前只做本地向导记录，预览和确认页明确显示“暂不提交”；后续接入饮食接口时再扩展为独立营养草稿。
- 服务端没有取消生成任务接口。“返回填写”仅停止当前页面轮询，已经提交的任务可能继续处理；正式计划保持不变。
- 赛事、阶段和测试计划目前没有独立的移动端持久化接口。准备比赛和赛后恢复页面会把比赛信息、恢复状态作为本次草稿上下文，只有用户确认应用后才会改变未来训练；不会在前端展示为已保存的赛事或阶段实体。
- “整个训练周期”明确禁用并提示暂未开放，不降级为周调整。“下一节训练”读取 `/workouts/next`，仅以该 ID 进行 `replace_workout`；无下一节时保留范围和输入并提示用户。

## 错误与安全状态

缺 FTP 或功体比目标缺体重时停在资料步骤并提示补录。生成失败留在任务页允许重新生成；校验阻断不打开确认弹层；应用失败保留草稿和同一应用幂等键，以便安全重试。所有 API 使用已有登录态；资料、提案和正式计划归属校验由后端执行。

既有正式计划也可能由人工课程创建，并不保证已有 AI 训练目标或每周可训练时间。已有计划页根据 `/ai-coach/readiness` 显示中文缺项，按钮进入对应的基础、目标或时间表单；保存后重新读取服务端就绪状态，再返回继续规划。不会仅凭 `hasActivePlan` 跳过资料检查，也不会在缺项时调用生成接口。

## 验证

移动端测试覆盖无 FTP 阻断、身体状态和周期信息传入生成请求、一周提案在确认前不应用、任务失败不改变正式计划、已有计划缺目标和时间的补录路径、已有计划的生成和调整入口、单节 AI 调整的预览/校验/应用、训练反馈记录、应用日期定位及首页随正式版本切换。执行 `pnpm --filter @ridepilot/mobile typecheck`、`pnpm --filter @ridepilot/mobile lint` 和 `pnpm --filter @ridepilot/mobile test`。真实模型生成的服务端联调记录见 `docs/features/ai-coach.md`；移动端尚未在实体设备上完成端到端真机验收。

## 2026-10-27 交互优化

- 首次建计划流程恢复为高保真参考的四步：骑行基础、训练目标、时间安排、饮食与禁忌；身体状态和安全症状并入骑行基础，饮食字段只在本地保存，不提交训练计划接口。
- 训练日历和课程详情增加“AI 调整”和“记录训练反馈”。单节调整默认只影响当前课程，服务端提案仍必须经过校验、确认、版本检查和幂等应用。
- 课程详情按课程 `source` 显示 AI 或手动来源，避免把 AI 课程标成手动课程。

- 建计划步骤统一使用 390pt 基准的黑金暗色令牌，增加步骤进度轨道、顶部返回入口、目标选项图标卡、最小 44pt 点击区域和 52pt 主操作按钮。
- 草稿预览改为计划摘要 Hero、课程数量/总时长指标、阶段说明和动作列表；确认应用使用带拖拽指示器的底部确认表单，明确版本变化与课程数量。
- 草稿生成后增加“选择计划方向”页面，再进入独立的计划差异预览；当前接口只返回一份真实推荐草稿，页面不伪造第二份候选。
- 训练反馈、单节 AI 调整和调整预览复用同一套底部表单、信息卡、状态选项和 AI 草稿对比样式，保持操作路径与首次建计划一致。

## 2026-10-28 路由稳定性修复

- 页面显示以当前 Expo Router 路由为准，Flow 阶段只保存表单和生成状态；只有生成完成或应用成功这类异步阶段变化才执行一次定向跳转，系统返回不会被旧阶段重新拉回。
- 增加已有计划任务卡的回归测试，覆盖重新规划入口和规划页面渲染。
- AI 教练流程子页面进入 `/coach/*` 路由后隐藏 Tabs 底部导航栏，避免在表单、生成和预览页面显示不可用的全局导航；状态中心入口仍保留 Tabs 导航。
- 重新规划选择“本周剩余训练”时，日历接口会为每节课程计算 `editable`：课程必须是今天或未来，且没有训练记录；只有存在可编辑课程才使用 `replace_week`，否则使用 `empty_week` 为剩余日期生成新计划。资料缺失会进入资料填写路由，完成后恢复原本周任务上下文再生成草稿。

## 首页闭环与调整范围修正（2026-10-30）

- 下一节：服务端按账号时区当天起、日期和同日序号选取当前正式计划首节未记录课程，无固定未来窗口；生成请求携带该课程 ID、所在周及快照版本。只替换该课程，其他课程复制保留。
- 本周剩余：周一至周日范围内只替换账号当地今天起未记录的课程；下周：严格使用下一周周一至周日。没有可替换课程时使用 `empty_week`，保留过去和已记录课程。
- 读取范围后重新校验正式版本，冲突时保留用户输入并提示重新选择；失败重试不改变已选课程/周，不扩大影响范围。
- 预览与确认页展示实际课程数、日期和替换数，不再统一写“当前一周”或“应用到今天”。单课调整应用超时使用原提案与幂等键重试，成功后由日历读取新版本 ID。
- 实际训练记录在未改动课程跨版本复制后继续回显；已记录课程禁止 AI/人工覆盖。首页、详情和饮食页操作返回后刷新真实数据。
