# Upstream coaching sources

The runtime loads `SKILL.md`, `references/power-zones.md` and one scene reference. Those files are RidePilot adaptations of the pinned MIT-licensed sources below. `upstream/` contains each original `SKILL.md`, selected unchanged references and each author's MIT license for auditing; the runtime never loads or executes that directory. No upstream script, MCP tool, filesystem workflow or automatic calendar write is enabled.

## RidePilot adaptation

- The original skills assume data from Strava, TrainingPeaks or Intervals.icu and may direct an agent to call tools, write files or publish workouts. RidePilot instead receives authenticated API data and emits a validated proposal that requires user confirmation.
- The originals also cover nutrition, fueling, running, swimming or gym work. The current API stage accepts cycling workouts only and excludes nutrition and external service synchronization.
- Source examples often rely on HRV, TSS/TSB, power curves, race routes or age. RidePilot cannot use those values unless they are actually supplied. Its first-week guidance remains conservative when training history is absent.
- Source ranges and templates are guidance. The TypeScript validator and current user data decide whether a candidate workout can become a proposal.

The complete MIT license and copyright notice for each copied source is preserved in `upstream/<source>/LICENSE`. Updating a source requires reviewing the new commit, reapplying these scope filters, recording the new pinned revision and rerunning coach tests plus a controlled live-model smoke test.
